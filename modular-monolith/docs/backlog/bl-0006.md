# BL-0006: High-Throughput Shared Memory IPC (MMF / Ring Buffer)

## Why
- Sub-millisecond or high-volume data streaming may need an alternative transport.

## What
- For sub-millisecond or high-volume data streaming (e.g., uncompressed image frames or large binary matrices), implement an alternative `IWorkerTransport` backed by `System.IO.MemoryMappedFiles` with a single-producer single-consumer (SPSC) lock-free ring buffer and `EventWaitHandle` signaling.
- Dependencies: BL-0001.

## Current state
- The existing backlog describes this state; it has not been reverified during this migration: IPC uses HTTP/1.1 or HTTP/2 over Unix Domain Sockets or Named Pipes (~20–200 microseconds latency).

## How
1. **Shared Buffer Allocation**: Memory-mapped backing files created in POSIX `/dev/shm` or Win32 named paging files with explicit ACLs.
2. **Zero-Copy Serialization**: Support direct buffer writing using `IBufferWriter<byte>` and zero-allocation MessagePack or flat buffers.

## Verification and acceptance
- Measure round-trip latency and verify cleanup as described below. Open question: define the benchmark environment, measurement method, and cleanup test scenarios.
- [ ] End-to-end roundtrip latency for 1MB binary payloads drops below 10 microseconds.
- [ ] Safe cleanup of shared memory files upon Host or worker termination.
