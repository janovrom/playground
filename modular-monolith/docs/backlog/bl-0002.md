# BL-0002: YARP Reverse Proxy for Dynamic Gateway Routing

## Why
- Manual public routes and typed clients do not provide generic dynamic routing or a streaming reverse proxy.

## What
- Introduce YARP (Yet Another Reverse Proxy) in `ModularMonolith.Host`. YARP routes incoming public paths directly to worker IPC endpoints (`unix://` and `http://pipe:`), streaming responses without buffering and propagating W3C trace identifiers and security claims.
- Dependencies: BL-0001.

## Current state
- The existing backlog describes this state; it has not been reverified during this migration: Host `Program.cs` manually declares all public endpoints (`/`, `/grid.svg`) and explicitly invokes typed clients (`RendererClient`, `ImageCacheClient`). There is no generic dynamic routing or streaming reverse proxy.

## How
1. **Dynamic Configuration Provider**: Implement an in-memory `IProxyConfigProvider` that reads routes and clusters dynamically from registered `IHostModule` instances and `WorkerManager.GetEndpoint()`.
2. **Custom Transport Forwarder**: Configure YARP's forwarder with custom `SocketsHttpHandler` instances using `UnixDomainSocketEndPoint` (Linux) and `NamedPipeClientStream` (Windows).
3. **Context & Header Propagation**: Pass `traceparent`, `tracestate`, and client claims to workers.

## Verification and acceptance
- Verify routing and endpoint updates on both transports. Open question: define the test selection and assertions for streaming and context propagation.
- [ ] Gateway routes requests matching module route patterns directly to worker endpoints via YARP.
- [ ] When a worker process crashes and restarts on a new endpoint, YARP cluster destination addresses update dynamically without restarting the Host.
- [ ] Both Unix Domain Sockets and Windows Named Pipes function seamlessly as YARP destination transports.
