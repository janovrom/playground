# BL-0002: YARP Reverse Proxy for Dynamic Gateway Routing

## Why
- Manual public routes and typed clients do not provide generic dynamic routing or a streaming reverse proxy.

## What
- Introduce YARP (Yet Another Reverse Proxy) in `ModularMonolith.Host`. YARP routes declared public paths directly to worker IPC endpoints, streams responses without buffering, and propagates W3C trace identifiers and a Host-signed internal security context.
- The shared module declaration owns route metadata. A manual Host catalog adapter registers runtime descriptors for BL-0002. BL-0003 can replace that adapter with generated registrations without changing YARP or `WorkerManager`.
- Current public worker routes are `/render/{**path}` and `/images/{**path}`. Existing Host routes remain local.
- Dependencies: BL-0001.

## Current state
- The Host retains manual `/`, `/grid.svg`, `/health`, and `/modules` endpoints.
- `SvgRenderer` and `ImageCache` worker endpoints remain private behind UDS on Linux and Named Pipes on Windows.
- `IHostModule` registrations currently provide typed clients and worker launch helpers. Shared module declarations now provide stable route metadata.

## How
1. **Module descriptors**: Read route attributes from one shared module declaration and materialize immutable `HostModuleDescriptor` values. Validate duplicate, overlapping, and reserved paths at startup.
2. **Dynamic configuration provider**: Publish YARP route and cluster snapshots when worker readiness or endpoints change. Remove destinations while workers are unavailable.
3. **IPC forwarder**: Use the existing `IWorkerTransport` handlers to connect YARP to UDS or Named Pipes. Keep logical destination addresses in YARP configuration.
4. **Internal context**: Replace any inbound internal-context header. Forward selected configured claims in HMAC-SHA256-signed JSON. Generate one random key per Host run and pass it only in worker environment variables.
5. **Failure and streaming**: Return a stable problem-details 503 when no destination is ready. Let YARP stream request and response bodies.

## Verification and acceptance
- [x] YARP routes declared `/render/*` and `/images/*` requests directly to worker endpoints.
- [x] YARP configuration changes when worker readiness changes and can replace endpoint state without restarting the Host.
- [x] UDS gateway routing passes an end-to-end Linux test.
- [x] A chunk-gated integration test receives the first response chunk before the worker releases the second chunk.
- [x] The Host strips spoofed context and forwards only configured claims.
- [x] Workers reject absent, tampered, expired, and wrong-key internal context outside `/health`.
- [x] Shared declarations and runtime descriptors provide a BL-0003 generator boundary without coupling YARP to concrete `IHostModule` types.
- [ ] Named Pipe gateway routing has native Windows run evidence.
