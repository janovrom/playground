# BL-0003: Roslyn Source Generator for Module Onboarding (`WorkerSourceGenerator`)

## Why
- Onboarding a module currently requires repeated manual registration and entry-point boilerplate.

## What
- An incremental Roslyn source generator (`ModularMonolith.Generators`) inspects module and client metadata and generates:
  1. Host DI extension methods for typed module client registration.
  2. Worker entry-point `Program.cs` invoking `WorkerHost.RunAsync`.
  3. Strongly-typed client interfaces and serialization helpers.
  4. `HostModuleDescriptor` registrations equivalent to the manual catalog introduced by BL-0002.

- Dependencies: None.

## Current state
- `ModularMonolith.Generators` discovers declarations from the Contracts assembly at compile time.
- The Host calls generated `AddGeneratedWorkerModules()` registration. The generated code contains literal module metadata and no runtime reflection.
- `IHostModuleCustomization` provides optional hooks for resource limits, worker arguments, and Host services. Modules with default behavior do not need a Host customization.
- Worker projects contain only an `IWorkerModule` implementation. The generator emits their `Main` methods.
- Client interfaces and endpoint metadata live in `ModularMonolith.Contracts`. The generator emits typed `HttpClient` implementations for JSON, text, byte, and no-content operations.
- Shared DTOs, internal context payloads, and problem details use System.Text.Json source-generation contexts.
- The image cache no longer uses Dapper. Direct `SqliteCommand` operations avoid trim warnings.

## How
1. **Compile-Time Generation**: Target .NET 10 Roslyn `IIncrementalGenerator` with zero runtime reflection.
2. **Deterministic Output**: Generator-driver tests compare repeated output. Host and worker projects emit inspectable files under their generated intermediate-output directory.
3. **AOT Compatibility**: Generated clients use `JsonTypeInfo<T>` from explicit `JsonSerializerContext` types. Generated DI wiring contains no reflection. All production JSON paths are source-generated.
4. **Stable Host Boundary**: Generate data for the runtime `HostModuleDescriptor` contract. Do not generate YARP routes separately from the shared module declaration.
5. **BL-0002 Compatibility**: Replacing the manual Host catalog with generated registration must not change `WorkerManager`, YARP, transport forwarding, or internal-context validation.
6. **Diagnostics**: The generator reports `MMG001` through `MMG008` for missing or ambiguous worker discovery, invalid or duplicate declarations, unknown clients, missing operation metadata, missing cancellation tokens, and unsupported client shapes.

### New module onboarding

1. Add the shared module declaration, proxy route attributes, DTOs, and annotated client interface in `ModularMonolith.Contracts`.
2. Add one worker class that implements `IWorkerModule`.
3. Add an optional `IHostModuleCustomization` hook only when the module requires non-default resource limits, worker arguments, or Host services.
4. Build the solution. The generator creates the worker entry point, descriptor registration, typed client implementation, and client DI registration.
