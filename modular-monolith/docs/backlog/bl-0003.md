# BL-0003: Roslyn Source Generator for Module Onboarding (`WorkerSourceGenerator`)

## Why
- Onboarding a module currently requires repeated manual registration and entry-point boilerplate.

## What
- An incremental Roslyn Source Generator (`ModularMonolith.Generators`) that inspects assemblies for module declarations (e.g. `[WorkerModule("svg-renderer")]`) and generates:
  1. Host DI extension methods for typed module client registration.
  2. Worker entry-point `Program.cs` invoking `WorkerHost.RunAsync`.
  3. Strongly-typed client interfaces and serialization helpers.

- Dependencies: None.

## Current state
- The existing backlog describes this state; it has not been reverified during this migration: Every module requires manual implementation of both `IHostModule` and `IWorkerModule`, manual registration in Host `Program.cs` (`builder.Services.AddHostModule<T>()`), and boilerplate `Program.cs` in each worker project.

## How
1. **Compile-Time Generation**: Target .NET 10 Roslyn `IIncrementalGenerator` with zero runtime reflection.
2. **Deterministic Output**: Output code must be inspectable (`<EmitCompilerGeneratedFiles>true</EmitCompilerGeneratedFiles>`).
3. **AOT Compatibility**: Generated serialization and DI wiring must be trimming-safe and Native AOT-ready.

## Verification and acceptance
- Verify module onboarding and the generated build. Open question: define tests for deterministic output, trimming, and Native AOT compatibility.
- [ ] A new module can be introduced by authoring a single module class and contract without duplicating boilerplate host and worker entrypoint files.
- [ ] The generator emits valid C# that builds with zero warnings under `<Nullable>enable</Nullable>`.
