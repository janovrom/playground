# BL-0001: Transport Layer Resilience & Connection Recovery

**Status:** Completed.

**Architecture:** [Worker request resilience](../architecture/worker-request-resilience.md).

## Why
- Worker restarts can interrupt requests and expose transport errors to callers.

## What
- A formalized transport resilience pipeline that handles transient connection resets during worker restarts, applies configurable request timeouts, and integrates with the supervisor's lifecycle events.
- Dependencies: None.

## Current state
- `WorkerClientFactory` creates named clients through `IHttpClientFactory`, using the module's Unix Domain Socket or Named Pipe endpoint. The endpoint remains allocated across worker restarts. `WorkerReadinessHandler` prevents sends while the supervisor reports a worker as `Starting`, `Restarting`, or `Stopped`.
- The Host uses `Microsoft.Extensions.Http.Resilience` for up to two transient retries with exponential backoff and jitter, bounded to 500 ms per retry. Per-module request timeouts use `Workers:<Module>:TimeoutSeconds` and default to 10 seconds. The grid routes map renderer transport failures and request timeouts to HTTP 503; cache failures use the fallback described in the architecture.

## How
- **Connection Recovery**: `WorkerManager` retains each allocated endpoint across process restarts. The HTTP handler rejects sends while the worker is unavailable; transient connection failures retry through the same endpoint, allowing the transport handler to establish a fresh connection after restart.
- **Connection Ownership**: The Host owns the pooled worker transport handlers and disposes them during service-provider shutdown. Handler disposal releases their IPC connections.
- **Backoff & Jitter**: The retry pipeline performs at most two retries with exponential backoff and jitter. Each delay is capped at 500 ms, and `Retry-After` is ignored so recovery attempts stay within the short restart window.
- **Health Status Integration**: Each outbound attempt checks that the worker is `Running`; requests are not sent to workers in `Starting`, `Restarting`, or `Stopped`.
