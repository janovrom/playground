# BL-0004: Unified Packaging Pipeline & Single Distribution Bundle

## Why
- Adding a module currently requires editing hardcoded Host packaging targets.

## What
- An automated MSBuild packaging workflow that dynamically batches all referenced worker projects into the `workers/` distribution directory, supporting both framework-dependent and self-contained publications.
- Dependencies: BL-0003.

## Current state
- `ModularMonolith.Host.csproj` identifies package workers with `PackageAsWorker="true"` metadata on direct project references.
- The `CopyWorkerOutputs` and `CopyPublishedWorkerOutputs` targets batch all marked references. They do not contain worker project names.
- Worker project references set `BuildReference="false"` and `Private="false"`. The Host packaging targets own worker build and publish execution, and worker files do not leak into the package root.
- The publish target forwards the Host configuration, runtime identifier, self-contained setting, apphost setting, trimming, and Native AOT settings to each worker.
- The Host and worker launch paths prefer packaged apphosts. The Linux systemd unit launches `ModularMonolith.Host` directly.
- CI verifies framework-dependent and self-contained package layouts on Linux and Windows.

## How
1. **Dynamic MSBuild Batching**: Mark each direct Host worker reference with `PackageAsWorker="true"`. Build `WorkerProject` from that metadata, then execute `Build`, `GetTargetPath`, or `Publish` for the complete batch.
2. **Distribution Layout**: Recreate the `workers/` directory on each build or publish, then produce:
   ```
   ModularMonolith.Host (.exe / ELF)
   appsettings.json
   appsettings.linux.json / appsettings.windows.json
   workers/
     ModularMonolith.Worker.SvgRenderer/
     ModularMonolith.Worker.ImageCache/
   ```
3. **Publication modes**: Publish each worker with the same RID and `SelfContained` mode as the Host. Framework-dependent and self-contained outputs contain worker apphosts.
4. **Deployment Script Compatibility**: Keep service and installer assets under their existing package paths. Linux systemd and Windows Service commands launch the packaged Host apphost.

### Add or remove a worker

Add a direct Host `ProjectReference`, set `PackageAsWorker="true"`, and keep `ReferenceOutputAssembly`, `BuildReference`, and `Private` disabled. The packaging targets discover the reference. Remove the reference to remove its worker directory. The targets remove stale `workers/` content before they package the current batch.

## Verification and acceptance
- `dotnet build modular-monolith/ModularMonolith.slnx -c Release -warnaserror`
- `dotnet test modular-monolith/ModularMonolith.slnx -c Release --no-build`
- Framework-dependent verification:
  - `dotnet publish modular-monolith/src/ModularMonolith.Host/ModularMonolith.Host.csproj -c Release -o <output>`
- Self-contained verification:
  - Linux: `dotnet publish modular-monolith/src/ModularMonolith.Host/ModularMonolith.Host.csproj -c Release -r linux-x64 --self-contained true -o <output>`
  - Windows: `dotnet publish modular-monolith/src/ModularMonolith.Host/ModularMonolith.Host.csproj -c Release -r win-x64 --self-contained true -o <output>`
- `tests/Verify-Package.ps1` derives expected workers from the marked project references and verifies Host files, apphosts, worker directories, runtime metadata, service assets, and absence of stale worker directories.
- [x] Running `dotnet publish ModularMonolith.Host -c Release` packages all marked workers into `workers/<ProjectName>` automatically.
- [x] Removing or adding a marked module project reference updates the published bundle without target edits.
