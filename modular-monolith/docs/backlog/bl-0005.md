# BL-0005: Circuit Breaking, Poison-Pill Quarantine & Dead-Letter Handling

**Status:** Done.

**Architecture:** [Tier 4: Resilience & Circuit Breaking](../architecture/overview.md).

## Why
- A payload that repeatedly crashes a worker can lead to a crash loop.
- Repeated worker failures can delay requests and reduce service availability.

## What
- Open a worker-specific circuit after a configured number of unexpected process exits within a rolling time window. Return HTTP 503 while the worker is unavailable.
- Fingerprint worker-bound requests. Quarantine a fingerprint after two correlated worker crashes within the correlation window and return HTTP 422 for matching requests.
- Store quarantined request metadata and raw bodies in bounded in-memory dead-letter storage.
- Provide loopback management endpoints to inspect dead letters and reset an open circuit.
- Dependencies: BL-0001, BL-0002.

## Current state
- `WorkerManager` counts unexpected exits after worker readiness. The default threshold is three exits in 120 seconds per worker. An open circuit suppresses restarts until an operator resets it.
- The Host fingerprints requests from the method, canonical path and query, and raw body. It buffers at most 1 MiB per worker-bound request and returns HTTP 413 before forwarding a larger request.
- Poison correlation occurs only when one distinct request fingerprint is active for the worker. A worker response clears that fingerprint's pre-quarantine crash evidence. Two correlated crashes within 120 seconds quarantine the fingerprint.
- Dead letters are stored in memory. The store holds at most 100 records and 10 MiB of raw bodies. FIFO eviction also removes the evicted fingerprint from the quarantine index. A Host restart clears the store.
- Management routes run on a separate listener at `127.0.0.1:5228` by default. They return 404 on other listener ports. The listener is configurable and has no application authentication; deployments that bind beyond loopback must restrict access at the network boundary.
- Typed worker clients retry only GET, HEAD, OPTIONS, and TRACE requests. YARP forwarding has no added retries.

## How
- `WorkerManager` stores rolling exit timestamps per worker, marks the circuit `Open` at the threshold, and waits for `POST /modules/{name}/reset` before restarting the worker.
- Request middleware buffers and fingerprints worker-bound requests, tracks active fingerprints, rejects quarantined requests, and records raw bodies in the bounded dead-letter store.
- The Host exposes `GET /modules/{name}/dead-letters` for metadata and `GET /modules/{name}/dead-letters/{id}` for the raw body.
- The management listener defaults to loopback port 5228. Configure it with `Management:ListenAddress` and `Management:Port`.
- The existing typed-client retry pipeline applies only to safe methods. The YARP forwarder remains without retries.

## Verification and acceptance
- `WorkerManager_OpensCircuitAfterCrashThresholdAndRestartsAfterReset` launches and crashes a real Linux worker. It verifies the circuit opens, suppresses restart, and restarts after reset.
- `UnixSocket_RepeatedPayloadCrashesAreQuarantined` kills a worker during two requests with the same active fingerprint. It verifies the second failure raises `PoisonPillException` and stores the request as a dead letter.
- `WorkerRequestTrackingTests` verify correlation ambiguity, response clearing, expiration, canonical path and query hashing, request-body replay and limits, quarantine rejection, and FIFO eviction.
- `ManagementListenerTests` verify default settings, public-port collision rejection, and listener-port isolation. A runtime check verified both public and management listeners bind, management routes return 404 on the public listener, and reset returns HTTP 409 while the circuit is closed.
- The `ModularMonolith.Tests` project passes on Linux. Windows-specific tests are skipped on Linux; run the Windows CI job to verify Named Pipe and Windows Job Object behavior.

- [x] Two correlated crashes quarantine the request fingerprint and store its raw body.
- [x] Ambiguous crashes are not attributed to a request; a completed worker response clears pre-quarantine evidence.
- [x] Matching quarantined requests return HTTP 422; oversized requests return HTTP 413; unavailable workers return HTTP 503.
